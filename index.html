    How I work with AI.

    Everything on this site was made in one Obsidian folder that Claude Code works in. The same folder runs my day job, my church's projects and a few side builds. This is how it's set up today; some of it will age badly.

    1. app codeskillNursePlusZeneathis site+1

      A brand library read out of the app's code

      The BorderPlus design system was built by reading the production app: tokens, 60 components, 12 guideline cards and a screen template. It's packaged as a Claude skill, and a lint rule flags code that drifts off-brand.

      Four projects use it, including NursePlus, Zenea and the demos on this site.

    2. one specWordPDFa page

      One shelf for brand files and converters

      Tokens, fonts and logos sit in one folder, next to converters for markdown to Word, HTML to PDF and a folder to a single-file page. A spec written once can go out as any of them.

      19 scripts across three projects pull from it.

    3. rootareaproject

      Rules every folder inherits

      One file at the root that nothing may weaken, one for each part of my life, one per project. A hook refuses any write that would put a long number into a confidential project's summary. It's crude, and it has caught real mistakes.

      How I write them

    4. this much

      Tokens, spent like money

      A session opens with the rules, the project's index and its last three log entries: about 2,500 of the 900,000 words. Ignore and deny rules keep PDFs, databases and login sessions out. Six small habit skills (plan first, check before saying done, keep the change small, and three more) let Sonnet and Haiku do the mechanical work.

      In the biggest project: 4,900 words read, of half a million.

    This site is the worked example: six days, 15 commits and 10 app recordings that a script made from my real prototypes. The four principles at the top of my root file are adapted from the Karpathy-inspired guidelines that went around in 2025; many of the other rules started as mistakes.
